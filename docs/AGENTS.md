# Documentation instructions

- `docs/` は、恒久的な決定の記録、背景、方針、公開契約、重要な制約に使う。コードからの推測が互換性のない変更や危険な変更につながる制約は明示する。
- 機能開発に伴って変わる詳細は、現時点の機能・スキーマ・テストを散文に書き写さず、それを所有する実装や生成リファレンスを参照する。
- 散文の 1 文は 200 Unicode 文字以内に収める。独立した内容は 1 文を複数行に折り返さず、別々の文・リスト項目・表の行に分ける。
- フェンス付きコードブロックや外側のパイプを持つ表では、構造上意味のある長い行をそのまま残す。分割できない単独のトークンも許容する。
- 残る物理行の制約は `make markdown-lint` で検証する。
