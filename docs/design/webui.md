# WebUI 方針

依存関係のキャンバスを選んだのは、因果関係こそがこのプロダクトを特徴づける情報だからである。
画面遷移と詳細表示は、その文脈を汎用的なダッシュボードの操作に置き換えず、保つべきである。

サーバの権威と credential の扱いは、[architecture.md](architecture.md) と [github-credentials.md](github-credentials.md) に従う。

WebUI の永続的な設定は、作業中に頻繁に切り替えるものを除き、Settings ダイアログを唯一の入口とする。

task ラベルの Settings・project・feature 編集面と、実効値の表示契約は [task-labels.md](task-labels.md) に従う。カード、グラフ、インスペクタは同じ snapshot の appearance を共有し、ラベル設定を表示箇所ごとに複製しない。
グラフのズームやサイドバーの project 展開のように頻繁に調整するものは、使う場所に置いたままでよい。

値を編集する面は、保存を 1 つに集める。Settings ダイアログ、task インスペクタ、project と feature の編集ダイアログは、面の中の項目ごとに保存を持たない。
Settings ダイアログの保存は、開いているタブに関係なく、そのダイアログが持つすべての下書きを書き込む。テーマのようにブラウザローカルに書くものも同じ扱いとする。
表示言語はブラウザローカルの設定ではなく、サーバの共有設定に置く。選択肢は `auto`・`en`・`ja` で、保存はサーバへ書き込み、表示はサーバが返した実効言語に従う。CLI が描くプロンプトと同じ言語にするためである。ブラウザローカルに残すのは初回描画で言語が切り替わって見えるのを防ぐキャッシュだけで、設定を取得した時点で実効言語に置き換わる。
そのため GitHub の host と認証は、行を選んでから別のフォームで編集するのではなく、行そのものを編集する。追加・削除・並べ替えも下書きへの操作であり、保存を押すまでサーバーには届かない。
保存ボタンは、保存するものがあるときだけ押せる状態にし、そのときだけ緑を点ける。この緑は押せることを示す色で、task のステータスが持つ緑とは別のトークンを使う。
これから書き込む下書きが不正なときは押せないままにし、理由をその場に出す。編集していない項目がサーバー上の値のまま不正であっても、保存を妨げない。
未保存のまま閉じようとしたときは、破棄することを確認する。確認をやめたときは編集も面もそのまま残す。
task の pull request の紐付けや参照ドキュメントの編集は、その task の項目ではなく別のレコードへの操作なので、この保存には含めない。

状態を表す色は、装飾ではなく状態の伝達のために確保する。
task のステータスの色は「今このタスクは誰のボールか」を軸に与える。緑は自身が対応可能、青は自身が対応中、黄は他者の対応待ち、紫は完了、灰は無効を表す。
赤はステータスの語彙には現れず、その task で手を動かす必要があるブロックラベル（コンフリクト・修正依頼・CI 失敗・未知のブロック）と、pull request 自身の異常に限る。
ステータスバッジの色は担当主体を示し、先頭のアイコンと分割ラベルは工程を示す。設計・実装・レビューの工程名を太く、その工程内の状態を通常の太さで並べ、完全な状態名は支援技術へ残す。
依存未解決はその task では動かせない他者の完了待ちなので、赤を使わず、枠線ではなく塗りつぶしのチップで示してステータスバッジと系統を分ける。
ステータスバッジ 1 個とブロックラベル 0〜4 個は、task カード・インスペクタ・グラフノードのどこでも同じ並びで出す。
task カードとグラフノードは、その task を今見なくてよいかを面自身で示す。見るべきものは枠と影を持つ浮いた面として、見なくてよいものは影を持たない地の面として出し、ステータスの色は借りない。
沈んだ面のうち、blocker 待ちのものは枠を破線で残す。決着した task と違って作業が残っているためである。
この破線は刻みが読める大きさで引く。刻みが細かすぎる破線は点線に潰れ、実線と区別できず、破線であること自体が伝わらない。線の太さは他の枠と同じ 1px を保ち、面の寸法も変えない。
沈んだ面も、薄い枠と地よりわずかに明るい面は残す。枠と面を地と同じにすると、canvas でも一覧でもどこまでが 1 つの task か読めなくなる。
pull request 自身の異常（情報が古い・GitHub ステータスの更新エラー）は、task カードとグラフノードでは pull request の行に置いたアイコンで示し、理由は tooltip と読み上げ用の名前に持たせる。
この tooltip はブラウザの title ではなく自前で出し、指した時点で即座に表示する。印は focus を受けるコントロールにして、キーボードでも理由に辿り着けるようにする。
これは task ではなく pull request の性質なので、task のステータスやブロックラベルの並びには混ぜない。破線も使わない。破線は blocker 待ちの枠のものである。
情報が古いことは他者待ちの黄、GitHub ステータスの更新エラーは赤とし、インスペクタが言葉で示すときも同じ色を使う。
pull request の名前が入り切らないときは、末尾ではなく先頭を省略する。Owner/Repo #Num のうち番号が同一性の要であり、番号を落とすとどの pull request か分からなくなる。
グラフノードでは、フィーチャーの pull request がすべて同じ host と owner にあるなら、その部分を名前から落とす。どれがどれかを分けない部分に狭い幅を使わないためである。
この判定はフィーチャーが持つ全 pull request で行う。完了済みの task を隠しても名前が変わらないようにするためである。
ステータスの色は面の浮き沈みで変えない。沈んだ面でも無彩色にせず、バッジは同じ色で読めるままにする。
沈むのは完了・クローズ・マージ済みと、未解決の依存を持つものだけである。決着した task には読むものが残っておらず、依存待ちの task は何を読んでも blocker が終わるまで動かせない。
沈んだ面は寸法を変えない。浮き沈みが一覧やグラフの並びを動かさないためである。
グラフノードは同じフィーチャーの中ですべて同じ寸法とし、ステータス・ブロックラベル・pull request・ドキュメントの有無で 1 件ずつ寸法を変えない。ノードの高さが変わると ELK は周囲のノードまで動かすためである。
その寸法は、フィーチャーで最もアセットが多いタスクに合わせる。どのフィーチャーでも最大寸法を取ると、アセットの少ないフィーチャーで必要以上に大きなカードになるためである。入り切らないアセットはノードの中でスクロールさせる。
ブロックラベルが折り返す 2 行目の高さは、ラベルがなくても常に確保する。ラベルは GitHub の同期で増減するので、これを寸法に反映すると同期のたびにフィーチャー全体が動く。
グラフノードの並びは、依存関係が許す範囲で task ID 順とする。互いにつながらないチェーンどうしの並びはこの規則の対象外で、離して置くことを優先する。
ステータスはヘッダのバッジが示すので、ノードの縁取りでは繰り返さない。
この軸が当てはまるのは task のステータスだけで、feature のステータスや pull request 自身の表示状態は独自の語彙と色を保つ。
識別子と数値には等幅フォントを使ってよいが、通常のコンテンツは英語と日本語での読みやすさを優先する。
本質的でないモーションは、reduced-motion の設定を尊重する。
押した操作が終わるまで待たせるコントロールは、押せなくするだけでなく、そのアイコン自身を動かして処理中であることを示す。押せない見た目は、処理中と実行不可のどちらでも同じに見えるためである。
この処理中は `aria-busy` でも公開し、動きを止める reduced-motion でも支援技術には伝わるようにする。ラベルの語は処理中でも変えない。押した位置のラベルが入れ替わると、同じボタンを目で追い直すことになるためである。

序数は、その順序自体が情報である場所にだけ表示する。
行に通し番号やレコード識別子など、読み手が使えない数値を持たせない。
位置・形・色がすでにどのフィールドの値かを伝えている場合、フィールド名は落とす。
視覚的な区別が色や配置だけの場合は、支援技術のために名前をマークアップに残す。
値だけでは曖昧になる場合や、他の場所の表現と読み手が突き合わせる必要がある場合は、可視のラベルを残す。

コントロールはアイコン優先とし、意味を伝えるのに言葉が要らない限りボタンはアイコンだけを持つ。
アイコンのみのコントロールには、アクセシブルな名前と tooltip を付ける。
対象・結果・危険の範囲をアイコンで伝えられない場合は、可視のラベルを残す。
ポインタ操作には、キーボードでも到達できる代替手段を用意する。
スクリムを敷くモーダルは Escape で閉じられるようにし、その閉じ方は可視の閉じる・キャンセルと同じ経路を通す。未保存の編集があれば Escape でも破棄の確認を挟む。
モーダルが重なっているときの Escape は、最も手前の 1 つだけを閉じる。書き込みの完了を待っている間は Escape でも閉じず、背後のモーダルにも渡さない。
Escape は焦点がモーダルの中にあるかどうかに依らず届かせる。焦点を持つ要素の位置で閉じられるかが変わってはならないためである。
一連の作業で行を選択するリストでは、行自体をコントロールにする。対象は端のチェックボックスではなく、読み手が読んでいるその行だからである。
この選択状態は `aria-pressed` で公開する。アクセントの縁取りや塗りつぶしの背景は、見た目だけで状態を表しているためである。

現在の画面・コンポーネント・ジェスチャ・コントロールの配置は、WebUI の実装とそのテストが所有する。
task 検索はブラウザ上で現在の Snapshot に対して動作する。q クエリは URL に残るので、再読み込み・履歴・共有で同じ表示が再現できる。
project 一覧および各 feature 一覧のステータスタブも、同じ理由で URL に残る。
ナビゲーションは project と、その中で進行中の feature のツリーである。どの行を折りたたんでいるかはブラウザローカルの状態とする。
サイドバーの幅と、サイドバーを隠しているかどうかも同じくブラウザローカルの状態とする。
隠すときはアイコン列に縮めず完全に消す。ナビゲーションは「ある」か「ない」の二択で、読み取れない中間状態を持たない。
幅と最小化が意味を持つのは、サイドバーが縦列になる画面幅だけである。横 1 行に変形する幅では隠さない。隠せばナビゲーションが丸ごと失われるためである。
task グラフが完了済みの task を隠すかどうかもブラウザローカルの状態とし、次回訪問時も前回のままのグラフを表示する。
同じグラフ内で task を名前などで絞り込む検索は、URL にもブラウザローカルにも残さない。1 回の閲覧の中で目的の task を見つけるための一時的な操作であり、再読み込み・履歴・共有でも次回訪問でも再現する必要がないためである。
この検索は空白で区切った語すべてを含む task だけを残す部分一致とし、`/tasks` の修飾子文法や引用符は持ち込まない。区切りは全角空白でもよい。語ごとに照合先は問わないので、title と assignee にまたがる指定もできる。単一の feature のグラフでは全件に一致してしまうため、feature 自身は照合の対象にしない。
非表示にすると、未完了の task に挟まれたものも含め、完了した task はすべて消える。
隠れた連鎖をまたぐ依存関係は、見えている両端に、隠れている task をすべて挙げた切断エッジとして現れ、依存の文脈を余さず保つ。

ローカルデータベースの変更は、ブラウザの操作を待たずに画面へ届く。
サーバが変更を検知してリビジョンを流し、WebUI はそれを合図にキャッシュを捨てて取り直す。運ぶのはリビジョンだけで、snapshot 本体は流さない。キャッシュの持ち主を 1 つに保ち、導出のロジックを二重に持たないためである。
CLI からの変更も別タブからの変更も同じ経路で反映される。サーバは自分の書き込みも他人の書き込みと同じく検知するためである。
ストリームはブラウザプロファイル全体で 1 本に絞り、受け取ったリビジョンをタブ間で配る。サーバは TLS なしの HTTP/1.1 なので、ブラウザは同一オリジンへの同時接続を数本に制限する。タブごとに 1 本張ると、数枚開いただけで残りの取得が接続待ちになる。
どのタブが張るかはロックで決まり、そのタブが閉じれば次のタブが引き継ぐ。ロックを扱えないブラウザでは、各タブが自分で張る。
接続が成立するたびに、リビジョンが変わっていなくても取り直す。これにより切断中の変更も引き継ぎ中の変更も次の 1 回の取得へ畳まれ、取りこぼしという概念が生じない。
変化がないときも一定間隔で同じリビジョンを送る。これがないと、無変化と接続の死亡をブラウザから区別できない。
サーバが変更を検知できなくなったら、ストリームは heartbeat を続けずにエラーで終える。無変化として送り続けると、更新が止まっていることをブラウザから区別できない。
接続が切れたら backoff を置いて張り直す。恒久的に張れなくなっても、ウィンドウのフォーカス復帰による取り直しは残るので、動作はこの仕組みが入る前と同じところまでしか落ちない。
自分の書き込みが起こした更新では取り直さない。書き込んだ側はその mutation の完了時にすでに取り直しており、二重の取り直しは画面を触っている最中に届いて操作を壊す。
取り直しは進行中のポインタ操作が終わるまで待たせる。依存をつなぐドラッグの最中にグラフを描き直すと、掴んでいた接続がその場で消えるためである。
この 2 つの帰結として、自分の書き込みと同じ検査周期に入った外部からの書き込みは、次の変更かフォーカス復帰まで届かないことがある。
そのため切断の表示は、30 秒以上つながらない状態が続いたときだけ出す。単発の切断は環境によって頻繁に起こり得るので、そのたびに警告を出すと表示自体が信用されなくなる。
購読しているブラウザが 1 つもない間は検査しない。常駐するサーバが、誰も見ていない時間帯まで毎秒起きて捨てるだけの読み取りをしないためである。
この経路の間隔はサーバの実装が持ち、設定ファイルには出さない。GitHub 同期の間隔設定とは無関係である。

demo モードは、RPC やドメインの状態ではなく、配信される HTML のメタデータで注入する。
開発サーバは HTML を自分で配信するので、demo の API に向けているときは同じメタデータを注入し、demo の画面をそのまま再現する。
WebUI は、すべての demo 画面の最上部に二言語のリセット警告を表示する。
画面全体を見たいときのために閉じるボタンを添える。閉じた状態は、demo の HTML を配信しているプロセスごとの ID と対にしてブラウザローカルに保存する。
そのため読み込み直しやホットリロードでは戻らず、demo のサーバを起動し直すと ID が変わって必ず戻る。demo であることを永続的に隠せる設定は持たない。
ブラウザローカルの言語・テーマ・ズームの設定は、一時的な demo 環境の外に置く。
